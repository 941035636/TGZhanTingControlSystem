# 技术架构

## 部署拓扑

```text
电脑浏览器 ── AdminWeb ─┐
                        │
触控终端 ────────────────┼── Windows Server ── 外部TTS服务
                        │
LED Unity + AVPro ──────┘

旧平板中控 ───────────────── 现场设备（独立运行）
```

## 通信原则

- 管理和业务API使用HTTP；
- 客户端首版使用20秒长轮询获取指令，后续可以平滑替换为WebSocket；
- 所有播放指令包含唯一ID、会话、模块、节点、动作、媒体URL、计划执行时间和内容版本；
- 触控端与LED端返回Received、Ready、Playing、Completed、Failed等状态；
- 服务端收到当前节点全部参与客户端完成状态后才推进下一节点。
- 活动会话支持Pause、Resume、Skip、Stop控制；Skip等待当前节点参与终端上报Skipped后推进。

## 内容发布

管理端发布后生成递增版本。素材上传使用原始HTTP请求体流式写入`Data/Media`，上传过程中
同步计算SHA-256，不把大文件整体载入服务内存。媒体通过`/media`提供给终端，管理端发布
前后均执行内容完整性校验。后续继续增加内容包下载、双端版本一致性检查、素材引用清理和回滚。

## 同步

服务端使用UTC计划时间统一调度。终端先准备媒体，再等待执行时间。现场部署时必须启用Windows时间同步；后续增加播放器进度上报和偏差校正。

## 安全

当前代码为开发骨架。生产部署前必须完成账号体系、发布角色授权、HTTPS、终端身份认证、操作审计和敏感配置加密，不得直接按开发配置上线。
