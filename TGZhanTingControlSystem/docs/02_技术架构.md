# 技术架构

## 部署拓扑

```text
电脑浏览器 ── AdminWeb ─┐
                        │
触控终端 ────────────────┼── Windows Server ── 外部TTS服务
                        │
LED Unity + AVPro ──────┘

旧平板中控 ───────────────── 现场设备（独立运行）
```

## 通信原则

- 管理和业务API使用HTTP；
- 客户端首版使用20秒长轮询获取指令，后续可以平滑替换为WebSocket；
- 所有播放指令包含唯一ID、会话、模块、节点、动作、媒体URL、计划执行时间和内容版本；
- 触控端与LED端返回Received、Ready、Playing、Completed、Failed等状态；
- 服务端收到当前节点全部参与客户端完成状态后才推进下一节点。
- 活动会话支持Pause、Resume、Retry、Skip、Stop控制；Skip等待当前节点参与终端上报Skipped后推进；
- 开始讲解前校验LED在线且内容版本与服务器一致；素材全部就绪时正常启动，部分素材失败时进入
  “受限可用”模式；LED在线即允许启动，内容版本不一致或素材缺失时在节点执行阶段按需下载，失败后按Skip/Stop策略处理；
- 服务端同一时间只允许一个活动讲解会话，防止多次点击产生并行播放；
- 活动会话写入`Data/Playback/active-session.json`，服务重启后恢复当前节点并重新准备；
- 终端注册持续上报应用版本、内容版本、就绪状态和同步说明。

## 内容发布

管理端发布后生成递增版本。素材上传使用原始HTTP请求体流式写入`Data/Media`，上传过程中
同步计算SHA-256，不把大文件整体载入服务内存。媒体通过`/media`提供给终端，管理端发布
前后均执行内容完整性校验。每次正式发布都会归档到`Data/ContentVersions`；管理端可以查看
历史版本并回滚，回滚不会覆盖历史，而是从选中版本生成新的递增版本。LED开机或重新联网后
主动拉取内容清单并补齐本地缓存，因此不依赖发布瞬间在线。素材引用清理仍待后续完成。

## 同步

服务端使用UTC计划时间统一调度。终端先准备媒体，再等待执行时间。现场部署时必须启用Windows时间同步；后续增加播放器进度上报和偏差校正。

## 安全

管理端使用Bearer会话和`Administrator / Publisher / Editor / Operator / Viewer`角色；生产账号支持多账号配置，
密码只保存PBKDF2-SHA256散列。触控端与LED端使用`X-TG-Terminal-Key`访问终端接口，正式配置中的终端密钥以
Windows DPAPI LocalMachine加密。安装器默认创建并信任现场HTTPS证书，Server/AdminWeb/媒体统一使用
`https://localhost:5443`；浏览器管理端保持同源访问，不开放任意来源CORS。发布、回滚、路线变更、讲解控制
和异常恢复继续写入JSONL操作日志。明文开发凭据只存在于`appsettings.Development.json`，且必须显式设置
`ASPNETCORE_ENVIRONMENT=Development`才会加载；基础`appsettings.json`没有可用凭据，不得复制开发配置到现场。
