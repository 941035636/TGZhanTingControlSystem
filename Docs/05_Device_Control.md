# 设备控制设计

## 1. 设计原则

- 讲解引擎只调用统一设备接口，不包含具体协议报文。
- 每种协议或厂商设备由独立驱动实现。
- IP、端口、串口参数、通道和命令全部配置化。
- 每次命令必须记录请求、确认、结果、耗时和错误。
- 设备驱动故障不能直接拖垮中控主服务。

## 2. 统一设备模型

设备配置包含：

- 设备 ID、名称、类型和安装位置。
- 驱动类型和连接参数。
- 在线状态、最后通信时间和健康状态。
- 支持的命令模板和状态点。
- 命令超时、重试、互斥和冷却时间。
- 启动、停止和故障时的安全状态。

## 3. 串口继电器

待补参数：

- 品牌型号和协议文档。
- COM 口、波特率、数据位、停止位和校验位。
- 继电器通道数及每个通道对应设备。
- 开、关、脉冲、查询状态报文。
- 脉冲持续时间、连续操作间隔和上电默认状态。
- 是否需要反馈输入确认设备实际动作。

驱动应支持串口占用检测、自动重连、报文校验、通道互斥和安全复位。

## 4. 红外探头

待补参数：

- 探头型号、供电、输出形式及接入设备。
- 输入是开关量、串口事件还是 TCP 事件。
- 触发目的：唤醒、开始、暂停、继续、离场结束或仅统计。
- 检测保持时间、防抖时间、冷却时间和重复触发规则。

红外事件先进入规则引擎，结合当前讲解状态判断是否执行，不能直接调用播放或设备命令。

## 5. TCP 设备

待补参数：

- 设备名称、IP、端口和网络拓扑。
- 长连接或短连接。
- 客户端或服务端角色。
- 文本、十六进制或结构化报文格式。
- 帧头、长度、校验、编码和粘包拆包规则。
- 登录、心跳、重连和状态查询方式。
- 每条命令的响应、错误码和幂等性。

## 6. 时间线设备动作

每个设备动作应包含：

- 相对讲解片段的执行时间。
- 目标设备和命令模板。
- 参数、优先级和超时时间。
- 是否阻塞讲解继续。
- 失败后重试、忽略、暂停或终止策略。
- 离开板块时是否执行补偿动作。

## 7. 测试工具

- 串口模拟器和报文收发监视器。
- TCP 设备模拟器，支持正常、延迟、错误和断线场景。
- 红外事件模拟器，支持抖动和连续触发。
- 继电器通道映射测试页。
- 全时间线无实物演练模式，设备命令只记录不下发。
